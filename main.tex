\begin{abstract}
Large language models (LLMs) are increasingly deployed as software-engineering
(SWE) agents that resolve real repository issues through multi-turn tool use.
These agents interact with repositories
through a \emph{harness} that defines their tools, call syntax, and
observations. As a result, an agent trained in one harness can overfit to its
interface and degrade when deployed in another: holding the model and tasks
fixed, changing only the harness shifts \swev{} accuracy by $9.2$ points. We
find that this variation is largely superficial. Across four production
harnesses, diverse tool interfaces reduce to a shared set of only $12$ semantic
actions. We formalize this common action space as the \HP{} and develop
semantics-preserving transformations between the protocol and concrete
harness interfaces, verified with zero mismatches over \numroundtrip{} real
actions. Building on this representation, we introduce \method{}
(Harness-INvariant Training), which re-renders each training trajectory under
counterfactual harness interfaces and anonymizes interface-specific cues,
encouraging the model to learn action semantics rather than memorize tool
conventions. Under compute-matched training, \method{} reduces the accuracy
lost on an unseen harness from $10.4$ to $4.7$ points and improves accuracy by
$7.7$ points when both the harness and the programming languages are unseen.
These results suggest that harness variation need not be a fundamental source
of distribution shift for SWE agents.
\end{abstract}

\section{Introduction}
\label{sec:intro}

Recent years have seen rapid progress in LLM agents for software engineering.
Given an issue reported against a real GitHub repository, an agent such as
\claudecode{}, \codexcli{}, \opencode{} or \openhands{} explores the codebase,
edits files, runs tests, and returns a patch, and SWE-bench
\citep{jimenez2024swebench} has become the standard measure of how often that
patch is correct. Underneath every such agent is a language model wrapped in a
scaffold: a system prompt that documents a tool set, a protocol for emitting
calls, an executor, and a formatter that returns observations. This wrapper,
the \emph{harness}, is what the model actually sees.

The four harnesses above all let an agent run shell commands and edit files,
but they disagree on nearly every detail of how: whether reading a file is a
first-class tool or a shell command, whether that tool is called \texttt{Read}
or \texttt{read} or \texttt{file\_editor} with
\texttt{command="view"}, whether output carries line numbers, and whether an
episode ends with a \texttt{finish} call or a plain reply. These are
presentational choices, and one would like them not to matter. They do.
Evaluating a single instruction-tuned model on a single task set and changing
\emph{only} the harness (Table~\ref{tab:e0}), \swev{} accuracy ranges from
$16.0\%$ to $25.2\%$, a $9.2$-point spread produced by nothing but the wrapper.

The gap has a simple origin. Agent training data is collected inside whichever
harness the data pipeline uses, and supervised fine-tuning on that data teaches
the task \emph{and} the surface at once, with no signal separating them. A tool
named \texttt{Bash} that takes a \texttt{command} argument and returns
untruncated output becomes as much a part of the learned policy as the decision
to run the test suite before editing. Deployment in a different harness then
presents a distribution shift that is, from the model's perspective,
indistinguishable from a change of task (Figure~\ref{fig:overview}, left).

We argue that this shift is avoidable, because the disagreement between
harnesses is superficial in a measurable sense. We parsed \numtraj{}
trajectories ($557{,}732$ steps, \numactions{} tool calls) from four production
harnesses whose declared tool counts range from $4$ to $21$, and normalized
every call into a semantic action. Twelve actions suffice: after normalization
only $0.04\%$ of calls fall outside the vocabulary (Table~\ref{tab:vocab}). The
harnesses are not doing different things; they are naming and packaging the
same things differently. We make this core explicit and call it the \HP{}. A
concrete harness is then the protocol plus a choice of \emph{surface}, and the
surface decomposes into five axes that can be set independently: tool
granularity and naming, call syntax, prompt documentation, observation
formatting, and turn conventions. The abstraction is not lossy: rendering a
protocol trajectory into a surface and parsing it back recovers the original
action sequence exactly, measured over \numroundtrip{} actions at \rtacc{}
(Section~\ref{sec:protocol}). This is a \emph{descriptive} claim about
harnesses that already exist, not a proposal for a new standard.

Exact invertibility is what turns the protocol from an analysis tool into a
training signal. If a real trajectory can be undressed into protocol form and
re-dressed in an arbitrary surface, then a single collected episode represents
an entire orbit of equivalent episodes. We introduce \method{}
(Harness-INvariant Training), which trains on that orbit
(Figure~\ref{fig:overview}, right). Counterfactual Harness Rendering (\chr{})
re-renders every trajectory under freshly sampled surface configurations, and
interface anonymization replaces tool names with meaningless identifiers on a
fraction of samples, so that reading the documentation rather than recognizing
the name becomes the only reliable strategy. \method{} needs no new task data
and no architectural change.

We fine-tune \basemodel{} on \claudecode{} trajectories and evaluate under real
harnesses that training never showed as coherent wholes, against a \control{}
that sees the same trajectories the same number of times in their original
harness. \method{} reduces the accuracy lost when the model is moved to an
unseen harness from $10.4$ to $4.7$ points on \swem{}, and gains $7.7$ points
when both the harness and the programming languages are unseen. Together, these
results reframe harness variation: it is not a property of the task that a
model must absorb, but a nuisance factor that a training pipeline can
marginalize over. Our contributions are summarized as follows:
\begin{itemize}
\item \textbf{A measurement.} Harness choice alone moves \swev{} by
  $9.2$ points for a fixed model and task set, and the harness that does worst
  is not the one with the fewest tools (Section~\ref{sec:exp}).
\item \textbf{The \HP{}, with an exactness guarantee that is measured rather
  than assumed.} A $12$-action vocabulary covers $99.96\%$ of \numactions{} real
  calls from four harnesses; surface rendering is exactly invertible on
  \numroundtrip{} actions (Section~\ref{sec:protocol}).
\item \textbf{\method{}}, a training method that multiplies existing
  trajectories along the surface axes, needing no new task data and no
  architecture change (Section~\ref{sec:method}).
\item \textbf{A compute-matched evaluation.} Against a control that sees the
  same trajectories the same number of times in their original harness,
  \method{} more than halves the cross-harness loss on \swem{}
  (Section~\ref{sec:exp}).
\end{itemize}

\section{The Harness Protocol}
\label{sec:protocol}

\subsection{Definitions}

\paragraph{Semantic actions.} Let $\mathcal{A}$ be a finite vocabulary of
semantic actions, each a pair of a verb and a typed argument record. We take
$\mathcal{A}$ to be the $12$ actions of Table~\ref{tab:vocab}, obtained by
normalizing four harnesses' tool sets rather than by design. A \emph{protocol
trajectory} is a sequence $\tau = \big[(c_t, a_t, o_t)\big]_{t=1}^{T}$ where
$a_t \in \mathcal{A}$ is an action, $o_t$ the semantic content of the resulting
observation with formatting removed, and $c_t$ the agent's reasoning text.

\paragraph{Harnesses as renderings.} A harness $h$ is a rendering function $R_h$
mapping a protocol trajectory to a surface trajectory: the concrete token
sequence a model consumes and produces. Writing $\mathcal{H}$ for the space of
harnesses, we factor the surface into five axes,
\begin{equation}
\mathcal{H} \;=\; A_1 \times A_2 \times A_3 \times A_4 \times A_5 ,
\label{eq:axes}
\end{equation}
with $A_1$ tool granularity and naming, $A_2$ call syntax, $A_3$ system-prompt
template and tool-documentation style, $A_4$ observation formatting, and $A_5$
turn and completion conventions. A harness is a point $h \in \mathcal{H}$;
sampling a point is sampling a synthetic harness.

\paragraph{Proposition 1 (round-trip exactness).} \emph{For every
$h \in \mathcal{H}$ realized by our renderer there is a parser $P_h$ with
$P_h \circ R_h = \mathrm{id}$ on the action sequence of every protocol
trajectory: exactly for the three syntax families with named tools, and up to
an operational equivalence $\simeq$ (a file read and the shell command that
performs it) for the shell-only family. In particular $R_h$ is injective on
actions, modulo $\simeq$.} Appendix~\ref{app:proof} proves this by
construction, one stage at a time: granularity and naming form an injective
table lookup, and each syntax family is a decodable encoding of the named
record, with a JSON escape encoding for the few values a family cannot carry.
The proof covers the design; Table~\ref{tab:roundtrip} checks that the
implementation meets the proof's premises on real data. For each of
\numroundtrip{} actions drawn from six corpora we render under randomly
sampled configurations spanning all four call-syntax families and parse the
result back, comparing the action verb and every argument. Agreement is
\rtacc{} with zero mismatches; $\simeq$ cases are counted as consistent, never
as exact. Two consequences follow. First, the composition
$T_{h \to h'} = R_{h'} \circ P_h$ is a well-defined, semantics-preserving
translation between any two harnesses, so the protocol acts as a normal form. Second, the identifiability assumption behind
augmentation-based representation learning, namely that the augmentation
leaves \emph{content} untouched and perturbs only \emph{style}
\citep{kugelgen2021self}, holds here by construction and by measurement, rather
than approximately as it does for image augmentation.

\paragraph{Interface invariance.} A policy $\pi$ is \emph{interface-invariant}
if its induced semantic behaviour is unchanged by surface transport: for all
$h, h'$ and all protocol states $x$,
$\tilde{\pi}\!\left(R_{h'}(x)\right) = \tilde{\pi}\!\left(R_{h}(x)\right)$, where
$\tilde\pi$ denotes the policy's output pushed back to protocol level. Deviation
from this equality is what we measure; the natural distance between two
harnesses is the number of axes on which they differ,
$d(h,h') = \big|\{\, i : h_i \neq h'_i \,\}\big|$.

\section{\method{}: Harness-Invariant Training}
\label{sec:method}

\begin{figure}[t]
\begin{center}
\includegraphics[width=\textwidth]{pic/main_v1.pdf}
\end{center}
\caption{The \method{} pipeline. (1)~Collect verified trajectories with a
teacher agent in a single real harness. (2)~Parse each trajectory down to the
\HP{}: a sequence of thought, semantic action, and observation, with all
surface formatting stripped and recorded. (3)~Re-render every protocol
trajectory under freshly sampled surface configurations (real, synthetic, and
anonymized vocabularies), producing counterfactual harnesses that never existed
but are semantically faithful to the original episode. (4)~Filter, sample to a
token budget, and fine-tune. (5)~Evaluate the resulting model on SWE-bench
under real harnesses that were never seen in training.}
\label{fig:pipeline}
\end{figure}

\method{} has two components, both of which touch only the data; nothing about
the model architecture or the training objective changes.
Figure~\ref{fig:pipeline} traces the pipeline end to end.

\subsection{L1: Counterfactual Harness Rendering}

Given a corpus of real trajectories collected in a single harness $h_0$, we
parse each into protocol form and re-render it under $M$ configurations sampled
independently from $\mathcal{H}$:
\begin{equation}
\mathcal{D}_{\chr{}} \;=\;
\Big\{\, R_{h}\!\left(P_{h_0}(\tau)\right) \;:\;
\tau \in \mathcal{D}_{\text{real}},\;
h \sim \mathrm{Unif}(\mathcal{H})^{M} \,\Big\}.
\end{equation}
The semantic content of every sample is identical to a real, verified episode;
only the surface is synthetic. This is domain randomization
\citep{tobin2017domain} applied to the agent interface rather than to visual
appearance, and the domain-generalization bound of \citet{benda2010theory}
supplies the reason it should help: training over a distribution of surfaces
shrinks the divergence term between the training and deployment interface
distributions.

Rendered samples are emitted in the native function-calling format that
production harnesses deploy: a top-level \texttt{tools} JSON schema, structured
\texttt{tool\_calls}, and \texttt{tool\_call\_id}-linked tool messages. \chr{}
data therefore merges directly with ordinary agent SFT data and preserves the
base model's tool-calling ability.

\subsection{L2: Interface anonymization}

Sampling from real vocabularies alone leaves a shortcut intact: each semantic
function has only a handful of attested names, so a model can still map
\texttt{Bash}, \texttt{bash}, \texttt{terminal} and \texttt{exec\_command} onto ``the shell tool'' by memorization. We therefore
draw tool names from three tiers: names harvested verbatim from real harnesses
but \emph{recombined across} them ($\approx43\%$ of samples), plausible names
that no parsed harness uses ($\approx27\%$), and meaningless pronounceable
identifiers ($30\%$). Canonical semantics are never anonymized: they remain in the tool
documentation, so under the third tier the documentation is the only channel
carrying the information needed to act.

\subsection{\cham{}: a harness whose surface is a configuration}

Real harnesses cannot be perturbed one axis at a time: there is no way to give
\claudecode{} \openhands{}'s observation format while holding everything else fixed. We
therefore implement \cham{}, an executable agent harness in which every surface
property is a configuration parameter drawn from the same five axes. \cham{}
really parses calls, really executes them against a workspace, and formats
observations according to its configuration, which makes it both the instrument
for single-axis controlled experiments and an environment for evaluation under
arbitrary synthetic harnesses.

\section{Experiments}
\label{sec:exp}

\subsection{Setup}

\paragraph{Model and data.} We fine-tune \basemodel{}
\citep{qwen3} on $5{,}000$ \claudecode{} trajectories over SWE tasks. After
dropping trajectories containing unmapped tools or fewer than three semantic
actions, $4{,}133$ remain; \chr{} renders each into $M=2$ counterfactual
surfaces, yielding $8{,}266$ samples that instantiate $\numsurfaces{}$ distinct surface
configurations and $11{,}205$ distinct tool names. All runs use $215$ optimizer
steps, global batch $32$, learning rate $5\times10^{-5}$, and a $256$K context.

\paragraph{The control that matters.} A mixture of real and \chr{} data contains
more tokens than the real data alone, so any gain could be bought by extra
optimization rather than by surface diversity. We therefore train a
\emph{compute-matched} control: the same real trajectories only, run for exactly
the same $215$ optimizer steps (about $6.2$ passes over the data) with an
identical schedule; the two runs' training scripts differ in two lines. Matching
\emph{sample counts} instead would have given the control $27\%$ more tokens,
since \chr{} samples are $34\%$ shorter than the originals.

\paragraph{Evaluation.} We report \swev{} ($500$ tasks) and \swem{} ($300$ tasks), each executed under three real harnesses: \claudecode{} (the source harness), \opencode{} and \openhands{} (both unseen during training).
Repeated submissions of an identical configuration give a run-to-run noise floor
of $\pm2.0$ points on the $500$-task set and $\pm1.0$ points on the $300$-task
set; differences below these are not interpretable.

Read as absolute accuracy, the only difference outside the noise floor is the
unseen-harness, unseen-language cell, where \method{} gains $7.7$ points
($93/300$ versus $70/300$; two-proportion $z \approx 2.11$, $p \approx 0.035$);

reading is insensitive to which arm has the higher absolute score.

The two benchmarks disagree, and we take the disagreement seriously rather than
averaging it away. Multilingual consistently favours \method{}; Verified shows
no effect. A hypothesis we can state but have not yet tested is that Verified is
Python-only and heavily represented in pre-training, so a model retains enough
memorized prior to recover from an unfamiliar surface, whereas Multilingual's
non-Python repositories force reliance on reading the interface, precisely the capability \chr{}
trains. If this holds, low-prior task distributions are the
regime where interface invariance pays, and evaluation emphasis should move
there.

\subsection{Planned ablations}

The compute-matched control rules out ``more gradient steps''. It does not
separate the contribution of surface \emph{diversity} from that of merely
\emph{changing} the surface once. The decisive ablation renders the same
$4{,}133$ trajectories into the same number of samples at the same token count
but draws a \emph{single} fixed configuration instead of $\numsurfaces{}$; a sweep over
the number of distinct surfaces then yields an accuracy-versus-diversity curve.

\section{Limitations}
\label{sec:limits}

\paragraph{Preliminary evidence.} One of six evaluation cells is significant
against the noise floor and two cells are still executing. We report the
incomplete cells rather than omitting them.

\paragraph{\openhands{} results are unusable.} Both arms time out on \openhands{} at high
rates ($25\%$ and $64\%$ of settled trials), traced to a proactive-compaction
threshold set above the context length actually reached, so per-step prefill
grows until the wall clock is exhausted. Until the threshold is corrected and
both arms re-run, no \openhands{} number enters a conclusion. We note, as a
hypothesis rather than a result, that the control times out $2.5\times$ more
often than \method{} under an identical evaluation configuration, which would be
a behavioural generalization signal that accuracy alone does not capture.

\paragraph{\opencode{} is not strictly zero-shot.} \chr{}'s first naming tier
harvests real tool names from all parsed harnesses, \opencode{} included. The
\method{} arm therefore saw \opencode{}'s \emph{vocabulary} recombined into
synthetic harnesses, though never \opencode{} as a coherent harness. A strict
zero-shot arm requires excluding the held-out harness's names from the pool.

\paragraph{Single model, single source harness.} All results use one base model
and trajectories from one source harness. Whether the effect scales with model
size, or holds when the source harness is \codexcli{}'s shell-only surface,
remains open.

\paragraph{Rendering into shell-only surfaces is not yet supported.} Our
renderer implements three granularities (split, unified editor, monolithic).
\codexcli{}'s shell-only form is parsed but not rendered: transcoding
\texttt{read\_file} into a shell command and recovering it is not exactly
invertible and would forfeit the guarantee of Proposition~1.

\section{Related Work}
\label{sec:related}

\paragraph{SWE agents and their scaffolds.} \citet{jimenez2024swebench}
established the benchmark; \citet{yang2024sweagent} showed that the
agent--computer interface itself materially determines performance, which is the
observation our work builds on and generalizes. OpenHands
\citep{wang2025openhands} is the most widely used open scaffold; R2E-Gym
\citep{jain2025r2egym} and SWE-smith \citep{yang2025swesmith} scale task and
environment supply but leave the interface fixed. We
are, to our knowledge, the first to treat the scaffold as a nuisance variable to
be marginalized out during training.

\paragraph{Invariance and domain generalization.} Domain randomization
\citep{tobin2017domain} and invariant risk minimization \citep{arjovsky2019irm}
pursue invariance by exposure and by penalty respectively; the bound of
\citet{benda2010theory} formalizes why exposure to a distribution of domains
helps. Our setting is unusually favourable to this family of methods: the
content-preserving property that \citet{kugelgen2021self} must assume of an
augmentation is here measured at \rtacc{}, and the group structure over
surface transformations is explicit rather than latent
\citep{higgins2018symmetry}. The algebraic reading of the protocol as a normal
form, under which differences rather than points compose, follows the analysis
of \citet{allen2019analogies}.

\section{Conclusion}

Agent harnesses differ far more on the surface than in substance: four
production harnesses, ranging from four tools to twenty-one and from
first-class file editors to nothing but a shell, reduce to twelve semantic
actions covering $99.96\%$ of $\numactions{}$ real calls. Making that core explicit
as the \HP{}, and verifying that the surface map is exactly invertible over
\numroundtrip{} actions, turns interface variation into something a training pipeline
can marginalize over. \method{} does so with no new task data and no
architectural change, and on \swem{} more than halves the accuracy an agent
loses when it is moved to a harness it has never seen. Aligning hidden
representations across renderings of the same decision point, which
Proposition~1 makes well posed, is the natural next step.

\section{Proof of Proposition 1}
\label{app:proof}

Proposition~1 states that the surface map of every harness our renderer
realizes is exactly invertible on the action channel. The proof is by
construction: the renderer is a composition of two stages, and each stage is
shown to have a left inverse. Section~\ref{app:setting} fixes notation,
Sections~\ref{app:naming}--\ref{app:shell} prove one lemma per stage,
Section~\ref{app:theorem} assembles them, and Section~\ref{app:premises}
lists the premises and states precisely what the measurement of
Table~\ref{tab:roundtrip} adds to the proof.

\subsection{Setting}
\label{app:setting}

\paragraph{Actions.} An action is a pair $a=(v,r)$ of a \emph{verb}
$v\in\mathcal{V}$ and a \emph{record} $r$. The verb set $\mathcal{V}$ has the
twelve elements of Table~\ref{tab:vocab} (the four \texttt{edit\_file}
sub-actions count as distinct verbs). Every verb has a finite set of parameter
keys $K_v$, each with a declared type (string, integer, boolean, or JSON
value); a record is a partial map $r:K_v\rightharpoonup \mathbb{V}$ from keys to
values of the declared type. Unset keys are simply absent; two records are
equal when they are equal as partial maps. $\mathcal{A}$ is the set of all such
pairs.

\paragraph{Configurations.} Of the five axes of Eq.~(\ref{eq:axes}), only
$A_1$ and $A_2$ touch the text of a call. A configuration $h$ contributes
\begin{itemize}
\item a granularity $g\in\{\textsc{split},\textsc{unified},\textsc{mono}\}$,
      which fixes the set $T_g$ of surface tools: twelve tools, one per verb;
      eight tools, one \emph{editor} tool shared by the five file verbs; or a
      single tool;
\item a tool-name map $N:T_g\to\Sigma^{*}$ and a parameter-name map
      $\Pi:K\to\Sigma^{*}$, where $K$ is the union of all $K_v$ together with
      the \emph{selector} keys of the editor and the single tool;
\item a syntax family $s\in\{\textsc{json},\textsc{xml},\textsc{yaml},
      \textsc{shell}\}$.
\end{itemize}
The remaining components (prompt template, documentation style, observation
decoration, turn conventions) are constant with respect to the action text and
play no role below.

\paragraph{Factorization.} On one action the renderer is
$R_h = E_s\circ N_h$, where the naming stage $N_h$ maps an action to a
\emph{named record} $(n,\rho)$ (a surface tool name and a record over surface
parameter names) and the syntax stage $E_s$ serializes the named record to
text. The parser is $P_h = N_h^{-1}\circ D_s$ with $D_s$ the block decoder of
the family. The shell family has no named tools and defines $E_{\textsc{shell}}$
directly on actions (Section~\ref{app:shell}). All four families share an
\emph{escape encoding} $E_{\mathrm{esc}}(a)$: a fenced block tagged
\texttt{call} whose single line is the JSON serialization of
$\{\texttt{action}:v,\ \texttt{args}:r\}$ with the canonical verb and keys.
Since JSON escapes newlines, the payload occupies one line and the closing
fence is unambiguous, so $E_{\mathrm{esc}}$ is decoded exactly by reading the
fence and applying the JSON parser. Every use of $E_{\mathrm{esc}}$ below is
therefore exact and bypasses the naming stage.

\paragraph{Premises.} The lemmas use four premises, each discharged in
Section~\ref{app:premises}:
\begin{itemize}
\item[(P1)] $N$ is injective on $T_g$;
\item[(P2)] $\Pi$ is injective on the key set of each surface tool;
\item[(P3)] (\textsc{json} only) no argument value contains a well-formed call of
      the same configuration;
\item[(P4)] values carry their declared types, and a string-valued JSON
      parameter is not itself a JSON document.
\end{itemize}

\subsection{Lemma 1: the naming stage is an injective table lookup}
\label{app:naming}

\paragraph{Lemma 1.} \emph{Under (P1), (P2) and (P4), $N_h$ is injective and the
inverse tables of the parser recover $(v,r)$ from $(n,\rho)$.}

\emph{Proof.} Let $\tau:\mathcal{V}\to T_g$ assign each verb its surface tool.
Under \textsc{split}, $\tau$ is a bijection and $N_h(v,r)=(N(\tau(v)),\
r\circ\Pi^{-1})$. Under \textsc{unified}, the five file verbs share the editor
tool, and $N_h$ adds to the renamed record one selector entry
$\Pi(\mathrm{sel})\mapsto\ell(v)$ with $\ell$ an injection of the five verbs
into the literals $\{\texttt{view},\texttt{str\_replace},\texttt{insert},
\texttt{create},\texttt{undo\_edit}\}$; all other verbs are treated as under
\textsc{split}. Under \textsc{mono}, every verb uses the single tool and the
selector carries one of twelve distinct literals. In each case the decoder
proceeds in three steps. (i) From $n$ it recovers the surface tool, because $N$
is injective (P1). (ii) If the tool is the editor or the single tool, it reads
the selector entry, which is present because the encoder always writes it and
unambiguous because the selector key is distinct from every data key of that
tool (P2); the literal determines $v$ because $\ell$ is injective. Otherwise
the tool determines $v$ because $\tau$ is a bijection on the remaining verbs.
(iii) It renames the data keys back through $\Pi^{-1}$, which is well defined
on the tool's key set by (P2), and re-types the values by the declared type
of each key, which returns the original values by (P4). Hence the decoder is a
left inverse of $N_h$ and $N_h$ is injective. $\square$

\subsection{Lemma 2: the named-tool syntax families are decodable encodings}
\label{app:named}

\paragraph{Lemma 2.} \emph{For $s\in\{\textsc{json},\textsc{xml},\textsc{yaml}\}$
and every named record $(n,\rho)$, $D_s(E_s(n,\rho))=(n,\rho)$; for
\textsc{json} this uses (P3).}

\emph{Proof.} Write $J$ for JSON serialization. $J$ is injective on finite
records with distinct string keys and values of the types above (every string
becomes a quoted string in which quotes, backslashes and control characters
are escaped), and $J^{-1}\circ J$ is the identity on them.

\textsc{json}: $E(n,\rho)$ is $J(\{\texttt{name}:n,\texttt{arguments}:\rho\})$
between an opening and a closing tag. $D$ scans for the opening tag, takes the
first brace after it and the shortest prefix that is a balanced object under a
string-aware bracket count, and applies $J^{-1}$. The output of $J$ is itself
such a balanced object, and braces inside its string literals are skipped by
the string-aware count, so the recovered prefix is exactly $J$'s output. A tag
occurring inside a value can only start a second candidate block; by (P3) that
block is not a well-formed call of the configuration and is rejected, so the
decoder returns the single record. In the structured tool-calling channel used
for training, the object is carried by the API rather than located by tag
scanning, and (P3) is not needed.

\textsc{xml}: if any value contains a closing marker of the family
(\texttt{</arg>}, \texttt{</invoke>}, or the opening of an invoke element),
$E$ routes the action to $E_{\mathrm{esc}}$, which is exact. Otherwise $E$
writes an invoke element carrying $n$ and, per key, an \texttt{arg} element
carrying the value: strings verbatim, other types as $J(\cdot)$. $D$ takes the
shortest span from the opening element to \texttt{</invoke>} and, inside it,
the shortest span from each \texttt{arg} opening to the next \texttt{</arg>}.
Because no value contains these markers, both spans are the intended ones;
newlines are matched, so strings come back verbatim, and non-string values are
recovered by $J^{-1}$ followed by re-typing (P4).

\textsc{yaml}: $E$ opens a fence tagged \texttt{action}, writes
\texttt{tool:} $n$, then one line per key. A value that is not a multi-line
string is written on the key's own line as $J(\cdot)$; a multi-line string is
written as a block scalar (\texttt{|-}) whose lines follow, each prefixed by
exactly four spaces, an empty line becoming four spaces. The fence closes at
column~0. No value can produce a line starting at column~0: single-line values
are on the key line with newlines escaped by $J$, and block lines are indented.
Hence the first column-0 fence after the opening is the true end of the block.
$D$ reads key lines at two spaces of indentation, collects the four-space lines
of a block scalar while stripping the prefix, and drops trailing lines that are
genuinely empty; the only such line is the one produced by the newline before
the closing fence, since empty value lines were encoded as four spaces. Scalars
on key lines are recovered by $J^{-1}$. $\square$

\subsection{Lemma 3: the shell-only family is exact up to $\simeq$}
\label{app:shell}

The \textsc{shell} family has no named tools, so the naming stage is empty and
$E_{\textsc{shell}}$ is defined verb by verb. Some verbs have no surface form of
their own in this family and are \emph{lowered} to the shell command that
performs them; the decoder then returns that command. This is the one place
where the round trip is not literally the identity, and we make the slack
explicit.

\paragraph{Operational equivalence.} Write $a\simeq a'$ when the two actions
induce the same environment transition and the same observation content, with
decoration removed, from every workspace state. The relation identifies:
a file read with the shell command that performs it,
$\texttt{read\_file}(p,s,e)\simeq\texttt{run\_shell}(\texttt{sed -n
\textquotesingle s,ep\textquotesingle{} }p)$ and $\texttt{read\_file}(p)\simeq\texttt{run\_shell}(\texttt{cat
}p)$; a search with the corresponding \texttt{grep} or \texttt{find}
command; a fetch with \texttt{curl}; two shell commands that differ only in
leading or trailing newlines; a submission whose message is empty with the
documented filler message; and an action with an argument the executor
ignores (the display label of a delegation, the \texttt{view}/\texttt{plan}
selector of a task-list update) with the same action without it.

\paragraph{Lemma 3.} \emph{For every action $a$,
$P_{\textsc{shell}}(E_{\textsc{shell}}(a))\simeq a$. Consequently
$E_{\textsc{shell}}(a)=E_{\textsc{shell}}(a')$ implies $a\simeq a'$.}

\emph{Proof.} We list the encoding and its decoding per verb.
\texttt{run\_shell}: the command in a fenced block tagged \texttt{bash}; a
command containing a fence goes to $E_{\mathrm{esc}}$. The decoder takes the
shortest span to the closing fence and strips outer newlines ($\simeq$).
\texttt{edit\_file}: a patch envelope. The header line carries the path, so a
path that is empty, contains a newline, has outer whitespace, or contains the
envelope terminator goes to $E_{\mathrm{esc}}$; the body carries the old and
new text line by line, each line prefixed by \texttt{-} or \texttt{+}, so any
content is expressible except one containing the terminator itself, which
goes to $E_{\mathrm{esc}}$. Insertion adds \texttt{@@ after line $k$} to the
header, creation uses an \texttt{Add File} header with \texttt{+} lines,
undo a \texttt{Revert Last Edit} header, and a replace-all edit, which no patch
expresses, goes to $E_{\mathrm{esc}}$. The decoder inverts each form line by
line and is exact. \texttt{delegate}: an envelope whose header carries the
agent kind and whose body carries the prompt verbatim (the terminator inside
the prompt goes to $E_{\mathrm{esc}}$); the display label is dropped
($\simeq$). \texttt{task\_track}: a \texttt{PLAN UPDATE} block whose body,
the list serialized by $J$ when structured, runs to the next block; a body
containing a block opener goes to $E_{\mathrm{esc}}$; the selector is dropped
($\simeq$). \texttt{web\_search}, and \texttt{web\_fetch} with an extraction
prompt: $E_{\mathrm{esc}}$, exact. \texttt{read\_file}, \texttt{search} and
\texttt{web\_fetch} without a prompt: lowered to \texttt{sed}/\texttt{cat},
\texttt{grep}/\texttt{find} and \texttt{curl} commands inside a \texttt{bash}
fence, decoded as \texttt{run\_shell} ($\simeq$). \texttt{submit}: the message
as plain text; a message that is empty or whitespace becomes the filler
($\simeq$), and one containing a block opener goes to $E_{\mathrm{esc}}$. The
decoder collects fences, escape blocks, patch and delegation envelopes and the
plan block, keeps the earliest non-overlapping ones so that a fence quoted
inside a patch body is not a second call, and reads block-free text as a
submission. In every case the decoded action is the original or its
$\simeq$-image, which proves the first claim; the second follows because
$\simeq$-images are unique up to $\simeq$. $\square$

\subsection{Proof of the proposition}
\label{app:theorem}

For a configuration with a named-tool family, Lemmas~1 and~2 give
$P_h\circ R_h = N_h^{-1}\circ D_s\circ E_s\circ N_h = N_h^{-1}\circ N_h =
\mathrm{id}$ on $\mathcal{A}$. For the shell family, Lemma~3 gives
$P_h\circ R_h\simeq\mathrm{id}$. A map with a left inverse is injective, so
$R_h$ is injective on actions, modulo $\simeq$ in the shell case. The
trajectory-level statement follows step by step: an assistant turn is the
reasoning text followed by the call blocks of that step, separated by blank
lines, and the decoder returns the text outside the blocks as the reasoning.
This is exact as long as the reasoning contains no block opener of the family,
which the normalization of Section~\ref{sec:protocol} guarantees by moving
every call out of the text channels. Two turn conventions absorb the final
reasoning into the submission message (the shell family, and the plain-reply
completion convention of $A_5$); we count them under $\simeq$. $\square$

Two remarks. First, the composition $T_{h\to h'}=R_{h'}\circ P_h$ is defined
on the image of $R_h$, so it is a total map between surfaces, and
$P_{h'}\circ T_{h\to h'}=P_h$ on that image: transport preserves the action
sequence exactly. Second, the observation channel is decorated rather than
encoded: $A_4$ adds line-number gutters on file views, wrapper tags, and
empty-output and error markers, all of which are stripped by the inverse
decoration, and may truncate long outputs to a character budget. Truncation
discards content by design, exactly as production harnesses do, which is why
Proposition~1 is a statement about the action channel.

\subsection{Premises, and what the measurement adds}
\label{app:premises}

(P1) and (P2) hold for every configuration the sampler produces. Tool names
are drawn from synonym pools with rejection of a name already used in the
configuration, and anonymized identifiers with the same rejection. For
parameters, the synonym pools of any two keys that share a surface tool are
pairwise disjoint, a static property of the name tables that we check
mechanically, and anonymized parameter names are drawn with rejection. (P3)
and (P4) are properties of the data: (P3) fails only if an argument value,
such as the content of a file being written, itself contains a well-formed call
in the configuration's own vocabulary; (P4) holds because the normalizer types
every argument when it maps a harness call to a protocol action.

The proof covers the design of the maps; the measurement of
Table~\ref{tab:roundtrip} covers the implementation and the data. Rendering
\numroundtrip{} real actions under randomly sampled configurations and parsing
them back checks (a) that the code realizes the encodings described above and
(b) that the corpus satisfies (P3) and (P4). Both hold: zero mismatches, with
the $\simeq$ cases of the shell family ($89{,}930$ actions, $4.8\%$ of the
total) counted as consistent but never as exact. A mechanical companion check exercises the encodings on adversarial
values rather than real ones: $600$ sampled configurations across all
families, each rendering $72$ actions whose arguments contain every family's
delimiters, empty strings, outer whitespace and newlines, Unicode and
$10{,}000$-character payloads, for $43{,}200$ render-parse pairs with zero
mismatches. Four of the escape conditions of Lemma~3 (a path with outer
whitespace or containing the terminator, a whitespace-only submission, a task
list containing a block opener, a replace-all edit) were added as a result of
this check; none of them occurs in the corpora of Table~\ref{tab:roundtrip}.
